# 既有每日任务投递到IP工作台

当前入口名为“热点早报”，仍兼容 `#radar`。人物=`people`、时尚界=`culture`、服装=`apparel`、AI=`ai`、财经=`finance`；未识别资料为`other`。旧`culture`且标题以“时尚界热点｜”起头映射时尚界，旧`other`且标题以“服装类热点｜”起头映射服装。左栏“热点早报”直接进入财经（`#radar~finance`），仍可选择全部或其他类别；旧`#radar`链接首次默认财经，后续保留所选类别；按对应日报日期读取，历史日期不限制在最近90天。

每天目标为人物10、时尚界5、服装5、AI 5、财经10。每条财经保留“可以怎么讲”、来源、发布日期和实际核对范围，覆盖宏观政策金融、产业科技能源、企业经营竞争、消费文旅生活服务、住房家庭资产、教育人口公共服务、就业收入分配、国际区域城市经济。劳动收入仅为其中之一，不将全部热点强行转为工资工时；来源充分时10条尽量覆盖至少4个方向，同方向通常不超过3条，重大事件可例外并写理由，不为平衡凑数。品牌合作与产品主张单列，不当成独立核实事实。已有公众号与小红书选稿规则不因新增财经池而改变。

复用现有日报结构与采集规则，不新增自动化、收费模型、平台登录或发布。目标是当前IP的创作目录，不是基础资料数据库，也不是原自媒体工作台目录。

由本机任务配置提供当前IP的绝对目录；命令必须明确带`--data`，缺失则停止，不默写旧库：

```sh
node scripts/workbench-daily.mjs context --data '/本机IP创作目录'
node scripts/workbench-daily.mjs import --data '/本机IP创作目录' --file '/当天实际工作台日报.json'
```

每次先读context中的动态关注名单、网页身份偏好、既有事件和当前编辑目标。新闻来源、原文日期、人物实名、原图、评论的实际观察时间及五栏数量继续按原任务要求核对；原图受限不以生成图冒充，缺口如实记录。JSON先原样保留再导入，相同内容重试返回duplicate，不重复创建日报；修订须合并已有内容并保留历史。评论与活动不因迁移而放宽读取或外发权限。

日报属于创作资料库，在“热点早报”查看。JSON、原文与原件进入创作资料完整备份。基础IP资料的ZIP单独保留；两份备份共同覆盖这个IP，任何一份都不应单独称作整个工作台的全量备份。

迁移只改既有任务的投递路径，保留任务ID、原聊天、准备/交付时刻、内容范围、通知和暂停状态。手动重放真实日报验证目的地与幂等性，不等于未来定时触发已发生。

竞品评论研究独立放在左栏“竞品评论洞察”（`#comments`），页内为“高赞评论 / 选题解读”；与“评论回复箱”分开。旧`#radar~comments`、`#topics~comments`书签继续进入同一竞品页。既有观众需求分类用于整理评论，不是财经题材的上限。

国内受众关联优先：优先中国政策、产业与民生；国际事件须有明确传导关系，不以单一海外来源凑满十条。


## 2026-11-16 财经编辑思考

当前目标为人物10、时尚界5、服装5、AI5、财经50，共75条；保留历史原数。财经覆盖八方向，教育升学、就业、住房、养老医疗均在范围内，不把所有话题转成劳动收入。完整日报最多100条，为历史补充留余地。

每条财经可携带 `editorial`：`judgement`、`audience`、`angle`、`opening`、`outline`（1–6项）、`needs`（1–6项）、`priority`（优先/备选/待补资料）、`reason`、`reviewedAt`。全日报最多3条优先。当前Codex任务逐条形成判断；不新增模型调用或收费API。新闻原文与推断分列，不把标题改写当作思考。没有该字段的旧条目正常读取。

工作台热点卡显示判断摘要和切口；详情支持编辑、保存和带切口转选题，日期工具可看最近3天。编辑保存需匹配最新 `baseDigestId` 与原 `eventId`+首来源；冲突时刷新，不能静默覆盖。补充思考只追加日报版本，不重放评论、博主核查或图片抓取。

历史补充脚本：`node scripts/workbench-editorial.mjs --data 明确创作库目录 --file 编辑思考JSON`。输入为对象或数组，包含 `day,baseDigestId,retrospective,items:[{eventId,sourceUrl,editorial}]`。使用 `--append` 时接收 `news` 新增数组，逐来源/标题去重并追加，不改旧事实、时间和其他栏目。回看分析记录真实整理时间；不得充作历史工作痕迹。

## 浅色界面与早报时间口径

工作台主页面及嵌入创作区使用统一浅色主题，不随系统深色外观变黑。主页面在最后载入 `light-workbench.css`，嵌入页复用原有主题标识与浅色变量，保留照片、视频和用户设置的日程颜色。

日报区分早报日期、计划交付、初版聊天实际交付、资料生成及分析补充/编辑时间。`reviewedAt`只表示真实分析编辑时间；后来补充的内容不能倒签到09:00，也不能声称随初版交付。未核到回执显示未知，不代表未推送。实际聊天交付不证明系统通知送达。

GET日报从当前库设置 `discovery.deliveryReceipts` 按日报日期读取可选回执（`deliveredAt`及来源证据），不改日报原文和历史版本；必须先核原聊天最终回复与该轮完成记录，不能预填。页面保存分析后继续保留本期交付字段。

既有09:00交付流程在准备阶段完成财经分析，验收每条必要字段；缺失则及时交代缺口并续补，不能把计划时间代替完成。历史补录和下午新增新闻属于后续版本，初版记录只证明初版。
