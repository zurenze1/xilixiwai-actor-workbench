# IP创作模块 v1.3.0 验证

2026-11-02。既有项目最小改造，复用本人content-workbench v0.10.4的实际功能。原站不被修改；模块数据在每个IP独立目录内保存。

## 一次性导入

先对原SQLite使用在线备份取得一致快照，保留原数据目录。运行：

```sh
node scripts/copy-creator-content.mjs --source /原数据目录 --snapshot /一致快照.sqlite --target /IP数据目录/creator-modules/IP-ID
```

目标数据库已存在时拒绝覆盖。复制历史日报、评论观察、公共活动、项目、资料版本、引用证据、脚本及固定版本；追踪各记录引用的实际原件，逐份校验SHA-256。原件使用独立副本/APFS克隆，不使用硬链接。迁移回执只保存在本地目标目录。模型密钥、任务队列和每日定时任务不复制；模型默认关闭。

## 已验证

- 隔离环境集成测试：同源代理、跨站拒绝、不同IP隔离、文本采集与引用、原文件上传及字节读回、分镜保存、固定版本及执行表CSV导出；正式副本已有版本的Markdown导出包含证据出处链接。
- 停服再启动保留项目、草稿与版本。一次性复制拒绝重复覆盖，并检查引用关系和原件哈希；备份恢复回读实际原件字节。
- 实际浏览器：新建分镜、填写0—5.5秒时间/口播/画面，保存刷新后仍存在；生产副本切换IP、读取历史内容、打开原图与已有分镜。
- 本机实际资料副本完成完整备份、解包校验和恢复；原站未被覆盖。本机资料数量、哈希和路径留在本地验收记录，不进入公开源码。

核心、后台、IP及新增创作模块测试分别运行；结果是技术验收，不替代使用者审美、移动设备、真实平台授权和长期定时任务验收。未执行真实模型调用或新增自动化。

## 边界

两个新模块与原八个业务板块保留各自数据结构，不自动双向同步选题/稿件。顶端“模块备份与恢复”包含创作数据库和原件；侧栏基础资料ZIP仅包含原八个板块。恢复生成新目录，需从新目录启动后再验证使用。用户资料、原件、数据库、配置及备份均不属于GitHub发布范围。

Markdown/JSON包含口播证据与来源；CSV执行表的“素材与出处”列来自实际关联的素材。没有挂接素材的行不会自动填入证据网址，带完整证据出处交付请使用Markdown/JSON。
