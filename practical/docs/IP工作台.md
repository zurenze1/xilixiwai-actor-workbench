# IP工作台 v1.3.0

面向老板个人IP与内容团队，从选题、创作、拍摄到发布复盘，同时跟进日程、商务和IP资料。复用“戏里戏外”的SQLite、附件、历史版本与ZIP备份，不需要新开云服务。

## 运行

需要Node.js 24.21及以上。Mac双击仓库根目录的 `启动IP工作台.command`，或者：

```sh
npm ci --ignore-scripts
npm run start:ip
```

打开 <http://127.0.0.1:4936/practical/ip/>。打开即进入本机工作空间，不注册、不填邮箱、不设密码。首次自动创建空白“我的IP”，可在IP资料库修改名称。服务绑定127.0.0.1，不能直接供另一台电脑访问。关闭启动窗口即停止服务；重新启动会读取原有数据。

默认数据目录为仓库根的 `runtime-ip/`，与演员版运行资料隔离，并被Git忽略。可用 `DATA_DIR` 指定已有数据目录。请勿删除数据库、密钥文件或原件目录。完整IP备份不含服务运行配置；迁机后启动程序，再从ZIP恢复为新IP。要保留全部运行配置，应在服务停止后妥善备份整个数据目录。

## 10个业务板块

| 板块 | 实际操作 |
|---|---|
| 今日工作台 | 待办、待IP审核、当天安排、待发布数量及制作进度，均来自已存资料 |
| 日程与任务 | 月历、按日新建日程、任务负责人和截止日期、时间重叠提示 |
| IP资料库 | 定位、经历、观点故事、产品服务、FAQ、素材授权和工作方法；附件保留原件 |
| 热点雷达 | 按日期查看人物、文化、AI、时尚与服装线索，保留原图、出处、历史日报和评论观察；当前IP独立保存 |
| 选题库 | 受众、问题、角度、证据与来源；确认后可转入稿件编辑 |
| 内容创作 | 稿件结构、正文、平台、负责人、审核人和确认日期；修改保留历史版本 |
| 分镜执行台 | 导入脚本逐句分镜，编辑时间、口播、画面、花字、转场和声音，上传原件、预览素材、保存版本与导出执行表 |
| 拍摄准备 | 关联稿件、时间地点、镜头和问题、可逐项勾选的准备清单、素材位置 |
| 账号矩阵与复盘 | 多平台账号、账号/作品累计快照、指标对比筛选和分页、矩阵任务；保留发布登记、CSV与复盘 |
| 商务合作 | 合作方、交付标准、合同附件、交付和回款日期；分币种计算待收 |

导航按使用流程排列：今日工作台与日程是日常入口；IP资料 → 热点 → 选题 → 文案 → 分镜 → 拍摄 → 发布复盘构成内容制作顺序，商务独立跟进。2026-11-02本次仅调整入口顺序与显示编号，原有路由、记录和模块保存方式不变；导航顺序不表示已接通模块间自动同步。

演员角色研读、表演训练、舞蹈、健康、宠物、复杂财税库存等入口不进入IP界面。原演员版仍在原入口，未删除原始功能或资料。

## 一次完整操作

1. 打开后直接使用“我的IP”，或新建IP；在IP资料库填写定位与可公开资料。公开方法提纲可选择加入，默认“待确认”。
2. 新建选题，写清受众、问题、证据。选题标为“已确认”后选择“转为稿件”。
3. 保存正文，送IP审核。确认人和确认日期填写后才能标为已确认。已确认的标题或正文再修改，会回到待审核；需先保存新稿再重新确认。
4. 从稿件安排拍摄。准备清单可勾选并保存。只有稿件已确认后才能登记拍摄完成或实际发布。
5. 登记发布平台、账号与计划时间；人工发布后补实际时间和链接。
6. 数据采集时填来源和时间。空值不补0。每条发布登记保留最新一次数据，旧值可从历史版本查看；本版不自动计算跨平台趋势或跨平台统一完播率。
7. 写复盘，把明确的下一步转为带负责人和截止时间的任务。

## 热点雷达与分镜执行台（v1.3.0）

两个模块复用本人 `content-workbench` v0.10.4 的实际编辑器和保存逻辑，包含共享内核；不是跳回原站的快捷链接。侧栏直接打开，顶端可在新标签页展开。每个IP单独使用 `runtime-ip/creator-modules/<IP-ID>/`，切换IP不会借用另一个IP的数据。新IP默认空白；复制历史资料必须显式运行一次性导入脚本，已有目标目录禁止覆盖。

分镜修改自动保存，也可手动保存；未保存时禁止切换外层IP或板块。素材库、引用证据、脚本与固定版本保留关联。两个新增模块与原八个板块的选题、稿件记录分别保存，本版不做自动双向同步。

**备份要分开做：** 在两个模块顶端点击“模块备份与恢复”，生成该IP创作模块的完整备份，包含实际原件并验证哈希；恢复为新目录，不覆盖当前目录。原八个板块继续使用侧栏的基础资料ZIP。迁机若要保留全部运行配置和两类资料，停服后备份整个 `runtime-ip/`。

一次性导入方式及验证范围见 [创作模块验收](IP创作模块验收.md)。复制不会包含原工作台的密钥、模型开关、运行任务或定时自动化；原站数据和运行服务保持独立。本次系统时区核验为Asia/Shanghai；历史出处时间保持原记录。

## 账号矩阵（v1.2.0）

进入“账号矩阵与复盘”，先添加账号，填写平台、平台账号ID和主页。账号数据快照记录采集日期、粉丝数、平台原显示及来源链接；作品数据快照记录原作品链接、已知发布日期、累计指标与来源。未知数据保留为空，不填0；日期只有天时不虚构采集时刻，不从作品ID推算发布日期。

- 总览显示账号数、已收录唯一作品数和具有播放/阅读读数的作品数；后者是指标覆盖数量，不是播放总量。
- 同一账号、同一作品多个快照只取最新一期作作品排名，不叠加历史快照；同日同口径重复会拒绝保存。同平台相同账号ID不会重复登记。
- 可按平台、账号、作品发布日期和指标筛选；发布日期未知的作品在设置日期范围时排除。账号规模不按作品日期筛选，也不将跨平台粉丝合计为去重受众。
- 作品指标为各作品当前累计值，不解释成窗口新增、增长曲线或个人贡献。万/w/+ 等显示保留近似或下限含义，列表将w写为中文“万”，详情保留原显示。
- 同一账号至少有两期同来源链接、同来源名称和同口径快照时才计算粉丝差值；不能将来源改变造成的差异当作涨粉。
- 矩阵工作提纲填写负责人和期限保存后进入“日程与任务”。“发布登记与运营复盘”可展开，沿用原稿件审核、发布和CSV流程。
- 完整IP备份包含矩阵账号及快照，恢复时重映射账号关联。归档账号后其指标退出矩阵；历史记录仍保留。

本版没有自动同步、OAuth授权和定时付费查询。账号主页不是接口授权。后续接通须先核实服务、授权、实际指标覆盖和费用，验证成功时间与失败提示后再称为已连接。历史资料由本机导入，公开源码不包含人物账号数据、快照、数据库或密钥。

开源取舍：已比较[Postiz](https://github.com/gitroomhq/postiz-app)（AGPL-3.0，需额外后端服务）和[Mixpost Lite](https://github.com/inovector/mixpost)（MIT，PHP/Laravel）。其已核实功能不能直接证明覆盖国内抖音、小红书，故复用现有Node/SQLite工程，不引入新部署栈或复制其实现。[Postiz分析范围](https://github.com/gitroomhq/postiz-docs/blob/main/general/analytics.mdx)。

接口依据：[抖音用户粉丝数据](https://open.douyin.com/platform/resource/docs/openapi/data-open-service/user-data/get-user-fans-count)需申请权限并获得用户授权；[小红书小程序开放能力](https://miniapp.xiaohongshu.com/doc/DC137160)不等于已确认该账号具备通用运营分析接口。查阅日期：2026-11-02。

## 数据与备份

侧栏“使用说明与数据备份”导出当前IP的基础业务记录、资料文字和对应附件，不包含新增创作模块的独立数据库和原件。恢复新建IP并重映射关联，原IP保留。单附件最大32MiB，基础资料ZIP解压总量上限160MiB（含清单），最多999附件。未经压缩的文字备份体积也计入上限。

CSV使用运营板块提供的表头模板。`稿件标题`必须唯一匹配当前IP中的稿件；时间用 `YYYY-MM-DDTHH:mm`。出现任何错误时整批不保存，确认后整批导入。CSV不覆盖原有发布记录；同作品请编辑原记录。账号和平台为人工登记字段，不代表平台已连接。

## 公开资料补充与适用范围

以下仅参考方法并编写原创工作提纲，没有复制图表、完整文章或第三方个人档案。查阅日期2026-10-31。

- [Strategyzer：Value Proposition Canvas](https://www.strategyzer.com/library/achieve-product-market-fit-with-our-brand-new-value-proposition-designer-canvas)：辅助梳理目标受众、阻力与预期收益，定位仍需用真实反馈验证。
- [StoryCorps：Great Questions](https://storycorps.org/participate/great-questions/)：参考开放式经历访谈的方式，改编为工作经历采集提纲；公开范围需本人确认。
- [YouTube：衡量反映观众黏度的重要时刻](https://support.google.com/youtube/answer/9314415?hl=zh-Hans)：复盘片头、停留、重看和流失位置。该平台阈值不能直接套用其他平台；高峰有多种解释。
- 拍摄前检查单为工作台原创，根据现场设备与工作方式删改。

本机版不自动发布或登录平台；创作模块可读取实际可访问的公开网页/RSS，也可导入已有日报。每日自动化、平台授权与模型没有因复制而接通，需要分别配置并核验。跨设备协作和在线托管需另行部署后台。

## 复用取舍

界面按祖老大确认的原“深蓝潮汐”演示版截图，复用原仓库 `web/style.css` 的靛蓝侧栏（#2e3a6b）、炭灰底色（#242424）、深灰面板（#2c2c2c）、白色文字和蓝色按钮（#303d6c），标题采用粗体无衬线。表单、下拉框、弹窗和日历统一为深色；不再采用此前误用的“日光水蓝”浅色主题。

2026-10-31 图片界面更新：八个板块各配一张新生成的原创AI工作场景；首页四个图片入口通向选题、内容、拍摄和复盘。标题、短说明和按钮直接显示在图片上，仍为可选择、可点击的网页元素。人物均为虚构成年人，不代表IP本人、客户或真实团队。图片、生成工具、完整提示词和哈希见 `practical/web/ip/assets/ip-scenes-v1/manifest.json`；网页图片共约2.12 MB，原始PNG不在公开版本中。界面继续使用原本机服务，无需额外图片服务。

已确认GitHub插件可读取原仓库代码。对照[PLANKA](https://github.com/plankanban/planka)、[Twenty](https://github.com/twentyhq/twenty)、[Vikunja](https://github.com/go-vikunja/vikunja)的公开功能与部署方向后，本轮选择复用自己的实战工程，避免引入独立看板/CRM服务及其部署依赖。没有复制这些第三方项目实现；本工程依赖许可继续位于 `docs/licenses/`。
