# 工作室经营模块

此目录使用主工程 `../bridge.js`，没有独立账号、数据库或样本经营关系。主工程将 `business-v1` 映射到管理员专属的隐藏经营项目；没有 `ActorStore.context().businessProjectId` 时本页拒绝打开，不能降级保存到普通剧组项目。

## 挂载与切换

主工程可嵌入 `business/index.html?embedded=1&theme=tide`（另支持 `butter/moss`）。切换工作室、退出账号或销毁 iframe 前，必须：

```js
await iframe.contentWindow.BusinessApp.whenIdle();
```

未提交的文本表单会作为经营草稿保存，登记后才计入统计。未提交的原件不能由浏览器重新填写，故 `whenIdle` 会明确阻止切换，要求用户登记或清空文件选择；保存失败也必须重试或保留本页。`actor:theme` 的同源父页面消息可更新主题；重新挂载时也从查询参数及 context 读取。

## 已实现的工作流

- 主体：公司、工作室、个人及其他主体登记；两个已登记主体之间的合作、授权、经纪管理或手动出资记录，可保存证据原件。程序不核验工商关系，也不预填任何现实人物或公司。
- 收支：登记应收/应付总额，按“名称 | 金额 | 到期日”设置分期。分期合计必须等于总额；实际到账/付款可分多次登记，不能超额，剩余与逾期依据真实填入记录计算。金额为整数分，支持 CNY/USD/EUR/HKD/GBP，按币种分组，不换汇、不混算。
- 票据：登记发票、收付款凭据、合同及其他原件，关联主体与收支事项，可按原始名称下载逐字节原件。系统没有验票或银行联网能力，不将手动登记等同审核通过。
- 资产：购置台账、领用、归还、维护、处置和实物盘点；不允许重复领用、未归还处置、删除被流水引用的资产。流水按登记日期先后记录，不把领用状态伪装成GPS位置。
- 税务：登记期间、截止日、地区、会计、确认日、申报日、缴纳日、人工进度与凭证。推进为会计确认需要姓名与日期；已缴纳需要金额、实际日期和原件。程序不自动计算税率，不连接税务申报，不判断凭证法律有效性。
- 品牌：权利类型、注册/授权编号、用途地域与期限；商品 SKU、整数库存入库/出库/盘点；渠道合作与附件。不能负库存，同一品牌 SKU 编号不能重复；盘点写实际总数。总览显示已到期及未来30天内到期的登记权利。
- 导出：各类台账、分期回款表、库存表均实际下载 CSV，UTF-8 BOM/CRLF/引号转义并防表格公式注入。经营完整备份通过 bridge 导出状态与原件；恢复前校验结构、原件SHA256及引用完整性，缺附件或模块不符时不会覆盖旧记录。密码、密钥等不属于模型字段，不进入导出。

删除有关联记录时会拒绝；请先处理有关联子记录。删除附件引用不物理删除原件，主工程保留历史版本。所有“已确认”“已申报”“已缴纳”是用户/会计录入的状态，界面明确标注。

## 验证

```sh
node --check practical/web/business/app.js
node --test practical/tests/business.test.mjs
node --test practical/tests/business.browser.test.mjs
```

12项纯数据测试及1项浏览器流程测试通过。浏览器测试运行真实 Chrome、真实主工程 bridge，对私有内存API夹具操作，无真实账号或私人数据。测试实际新增主体、刷新保留草稿、分期及部分回款、下载CSV、资产领用、上传缴纳凭据、原件字节匹配、缺附件备份拒绝及保持旧记录；320/390/1440共21视图无横向溢出和脚本错误，全部数据请求只进入经营隔离项目。真实服务器的成员权限、跨工作室隔离、并发冲突与部署仍由主工程统一验收。

已核对 [ERPNext](https://github.com/frappe/erpnext) 的账务、资产与库存业务分类；未拷贝其GPL代码或引入整套ERP。当前模块为独立小型实现，无新依赖。
